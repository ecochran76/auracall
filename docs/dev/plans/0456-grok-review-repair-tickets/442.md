## What to build

Resuming a saved Grok history cursor from a fresh lazy-loaded view eventually reaches older rows without exceeding the configured page, time or cancellation bounds.

Review priority: P1. Source: accepted review finding SPEC3, review commit a86dccd9516e8b974438419a1f9d96d1b394e5d6; implementation reviewed at dabde7cafe3ae9b0c64757b9a0f27c3e96a56a10.

## Acceptance criteria

- [ ] A regression reproduces a two-page view returning a–d once, then returning no rows and the same cursor forever while e/f remain discoverable.
- [ ] An unchanged discoverable history with a valid continuation makes forward progress across bounded calls; replaying the anchor cannot consume the same entire budget indefinitely.
- [ ] The repair preserves page/time limits, foreground yield, cancellation, scope/account isolation and duplicate prevention; it does not fix progress by silently removing bounds.
- [ ] A missing or changed anchor produces an explicit safe restart/partial outcome rather than silent skipping or an endless unchanged continuation.
- [ ] Controlled-CDP tests cover dialog closure or fresh-tab restart through public discovery and mirroring, with consistent CLI/API/MCP/Ops continuation status.
