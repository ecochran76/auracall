# T02: Admit owned Grok backend requests before dispatch

Status: proposed; not a published implementation issue.
Parent: https://github.com/ecochran76/auracall/issues/398

## What to build

Apply a distinct account-wide request budget to actual owned Grok traffic generated by public reads and later lifecycle operations.

## Blocked by

- T01: Govern Grok reads and expose effective account controls

## Acceptance criteria

- [ ] Measure and document request categories and coverage before proposing numeric ceilings.
- [ ] Each unique owned backend request gets one pre-dispatch permit; duplicate observations do not double-charge.
- [ ] Cross-process/profile callers cannot bypass caps; manual/foreign traffic is excluded.
- [ ] Warning/cancellation/uncertain transport states remain fenced; Ops distinguishes operation usage from request usage.
- [ ] Validate public behavior with the agreed source/installed/live evidence distinctions; update operator docs and decision traceability.

No live effect is authorized by this draft. Bind exact target and authority in the execution packet.
